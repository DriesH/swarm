# Only the app uses the terminal socket

The daemon's terminal socket can list, read, type into and kill every terminal, user terminals included. Agents run as the same macOS user, so file permissions alone cannot keep them out. The daemon therefore refuses any peer whose process ancestry leads back to the daemon itself (every agent and terminal program is its descendant), and the agent harness gets its own socket that never exposes user terminals (ADR 0006).

A single socket with per-request permission checks was considered. It would mix two trust levels in one protocol, and one missed check would hand an agent the user's terminals. A Developer ID signed daemon also checks the peer's code signature through its audit token: the peer must be `com.swarm.app`, Developer ID signed by the daemon's own team. An ad hoc or unsigned daemon (a development build) skips that check. A daemon that cannot work out its own signature refuses every peer, and a release build knows its team at build time, so it can never skip the check.

The audit token alone is not enough. It follows the last process that touched the socket, and after `exec` it names the new program. A process outside the daemon's tree could queue requests, hand the socket to a helper, and `exec` the signed app before the daemon reads the token. So the daemon pins the token it checked and closes the connection when the token changes, and after `Hello` it sends a random challenge that the next frame must echo. Requests queued before the `exec` cannot hold the challenge, and a helper that answers it changes the token. XPC, which carries the sender with every message, was considered and left out: it needs a launchd service and a second transport next to the socket protocol.
